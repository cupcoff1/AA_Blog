# 学习笔记

## Java / Spring Boot

### @Autowired vs @RequiredArgsConstructor

- `@Autowired` — 字段注入，Spring 反射塞值，不推荐
- `@RequiredArgsConstructor` — Lombok 根据 final 字段生成构造器，Spring 自动调用，官方推荐
- 构造器注入好处：可测试（new 时传 mock），不依赖反射
- 手写构造器注入 = `@RequiredArgsConstructor` 效果一样，区别在是否用 Lombok 自动生成

### JwtInterceptor 校验链路

```
请求进入 → preHandle()
  → OPTIONS? → 直接放行（CORS 预检）
  → Header 无 Authorization? → 401 "请先登录"
  → Token 签验失败? → 401 "Token 无效"
  → Token 已过期(exp)? → 401 "Token 已过期"
  → 验签通过 → 解析 sub(用户名) → 写入 request.setAttribute → 放行
```

- `ExpiredJwtException` 是 `JwtException` 子类，catch 顺序必须先子后父，否则过期会被父类吞掉
- parseToken 验签成功后把用户名写入 request 属性，后续 Controller 通过 `req.getAttribute("username")` 获取

### OPTIONS 预检请求

- 浏览器跨域前自动发 OPTIONS 探路，不带 Token
- JwtInterceptor 必须放行 OPTIONS，否则前端连正常请求都发不出去
- 同源：协议 + 域名 + 端口 三者完全一致，任何一项不同即跨域
- 生产环境用 Nginx 代理，前后端同域名同端口，不存在跨域；开发环境才需要处理

### @Data + @AllArgsConstructor 后无参构造没了

- Java 编译器规则：一旦显式写构造器，就不再生成默认无参构造
- Lombok 的 `@AllArgsConstructor` 等同手写全参构造
- 解决方案：加 `@NoArgsConstructor`

### @Transactional 作用

- 方法内所有数据库操作要么全成功，要么全回滚
- Spring Boot 开箱即用

### MultipartFile

- Spring 对 HTTP 上传文件的统一抽象，不管原文件是什么格式
- `getOriginalFilename()`, `getContentType()`, `getSize()`, `transferTo()`

### Files.createDirectories()

- 递归创建目录，已存在则跳过，不用手动判空
- 注意是带 s 的版本，单数版本遇已存在会抛异常

### Paths.get() / Path.resolve()

- `Paths.get("a", "b")` — 跨平台拼接路径
- `dir.resolve("file.jpg")` — 拼接目录 + 文件名

### WebMvcConfigurer.addResourceHandlers

- 把 URL 路径映射到磁盘目录，使上传的文件可直接通过 URL 访问
- `addResourceHandler("/uploads/**")` → `addResourceLocations("file:./uploads/")`

### Stream / Lambda

- `stream().map(Entity::getField)` — 方法引用，等价于 `x -> x.getField()`
- `stream().filter()` — 过滤
- `stream().collect(Collectors.toList())` — 终止操作，触发执行
- `Collectors.groupingBy(Field::getKey)` — 按字段分组
- `Collectors.toMap(Key::getter, Value::getter)` — 需要指定 key 和 value
- 流是惰性的，`collect` 才真正执行

### 全局异常处理器

- `@RestControllerAdvice` + `@ExceptionHandler`
- Controller 只做路由，异常交给全局处理器统一返回 Result 格式
- 分层：`IllegalArgumentException` → 400，`Exception` → 500
- 生产环境 500 不应暴露内部错误信息，用 `log.error()` 记录

### slug

- URL 友好的唯一标识，字母数字连字符组成
- 中文标题 → 拼音 → 小写 → 连字符连接
- 用途：文章/标签的 URL 路径段

### JWT 认证

- 管理员 JWT：只存 username
- 评论者 JWT：存 username + avatar（claim）
- 拦截器校验 `Authorization: Bearer <token>`，解析后放 request 属性
- 管理员和评论者共用同一 JwtUtil，不同生成方法

**JWT 三段结构**：`header.payload.signature`，用 `.` 分隔

- Header：Base64({ "alg": "HS256" }) — 声明签名算法
- Payload：Base64({ "sub": "AA_", "iat": ..., "exp": ... }) — 存用户数据（不存密码，Base64 可解码）
- Signature：HMAC-SHA256(header + "." + payload, secret) — 防篡改

**后端职责**：
- 生成：用户名 → 拿 secret 签名 → 返回通行证给前端（不存数据库）
- 校验：收到通行证 → 拿 secret 验签 → 解码拿用户 → 放行
- 类比：景区印票（签名）→ 验票（验签）→ 不保留购票记录（无状态）

### 评论嵌套实现

- 数据库：`parent_id` 自引用
- 查全部评论 → 过滤 parent_id != null 的分组 → 挂到主评论的 children
- 2 层限制：create 时校验父评论的 parentId 必须为 null
- 级联删除：先删子回复再删自己

- redirect_uri 需要 URL 编码

- 不在 application.yml 里写明文密钥
- 用 `.env` 文件（spring-dotenv 读取）+ `.gitignore` 排除

### HikariCP 连接池

- `HikariPool-1 - Start completed` → 连接池初始化就绪
- 不是线程，是数据库连接池：预先建好 N 个连接，请求来了直接拿，用完归还，循环复用
- 每次重建 TCP 连接太贵，连接池避免重复开销
- Spring Boot 默认集成 HikariCP，性能最强，默认 pool size = 10

### jjwt 库 vs JwtUtil

- jjwt 提供的是零件（`Jwts.builder()`、`Jwts.parser()`），不是现成工具类
- JwtUtil 是自己写的，用 jjwt 零件拼装业务逻辑：决定存什么字段、exp 多久、异常怎么处理
- 类比：jjwt = 乐高零件，JwtUtil = 拼好的成品

### 数据库连接报错排查

- `Access denied for user 'root'@'localhost' (using password: YES)` → MySQL root 密码写错了
- 改 `application.yml` → `datasource.password` 为正确密码
- 还需要确保数据库已创建：`CREATE DATABASE IF NOT EXISTS aa_blog`

### MyBatis-Plus

- `LambdaQueryWrapper` — 类型安全的查询构造器（`eq(Blog::getSlug, slug)`）
- `selectCount(null)` — COUNT(*) 查询
- `selectBatchIds(ids)` — WHERE id IN (...) 批量查询
- `BaseMapper<T>` — 自带 CRUD 方法
- `@TableName` — 指定映射表名，不加则类名驼峰转下划线

### `@JsonProperty("snake_case")`

- 强制 JSON 序列化字段名为蛇形
- Java 驼峰 `parentId` → JSON `parent_id`

## 项目架构

### MVC 分层

```
Controller → Service → Mapper → DB
    ↑           ↑
  DTO(vo)   DTO(request)
```

- Entity：数据库表映射
- Mapper：MyBatis-Plus BaseMapper
- Service：业务逻辑 + @Transactional
- Controller：路由 + 参数校验
- DTO/request：入参
- DTO/vo：出参
